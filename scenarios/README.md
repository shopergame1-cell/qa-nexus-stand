# Шість корпоративних сценаріїв (TASK-55.2)

Кожен сценарій — це реальна ситуація, у яку людина потрапляє в перший тиждень у команді.
Пул сценаріїв спільний для всіх студентів.

| Сценарій | Ситуація | Що перевіряє check.sh |
| --- | --- | --- |
| [01](01-internal-dependency/) | залежність є лише у внутрішньому репозиторії | репозиторій оголошено в pom + збірка проходить у чистому кеші |
| [02](02-auth-id-mismatch/) | 401 при правильному паролі | id сервера = id репозиторію, пароль зашифровано, деплой проходить |
| [03](03-mirror-too-wide/) | mirror перехопив усе | `mirrorOf` звужено (не `*`) |
| [04](04-snapshot-policy/) | свіжий snapshot не підтягується | `updatePolicy` дозволяє оновлення + залежність справді snapshot |
| [05](05-local-only-artifact/) | «у мене працює, у колеги — ні» | є `distributionManagement`, артефакт доступний у репозиторії, чистий кеш розвʼязує |
| [06](06-version-conflict/) | дві версії однієї бібліотеки | версія зафіксована явно + у дереві одна версія |

Запуск будь-якого сценарію:

```bash
bash setup.sh     # створює зламаний стан (перед цим: docker compose up -d && bash setup-repos.sh)
bash check.sh     # перевіряє стан; до правки мусить падати
```

Автоперевірка в CI (`.github/workflows/scenarios.yml`) для кожного сценарію робить три кроки:
запускає `setup.sh`, переконується що `check.sh` **падає** (стан справді зламаний),
застосовує еталонний розвʼязок із теки `solution/` і переконується, що `check.sh` **проходить**.
Так перевіряється не лише «студент має що робити», а й що задача розвʼязувана.
